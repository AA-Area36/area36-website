# Fix GDrive Worker Resource Limits (Error 1102)

## Problem Summary
Pages are crashing with Cloudflare Worker Error 1102 "Worker exceeded resource limits" when GDrive modules are bundled into page bundles through server action imports.

## Root Cause Analysis

### Issue 1: Server Actions Importing GDrive Modules (CRITICAL)
Client components import server actions, which import `lib/gdrive/*` modules. This causes the entire GDrive module tree to be bundled and evaluated at page load time.

**Offending imports:**
| Client Component | Imports From | Which Imports GDrive |
|-----------------|--------------|---------------------|
| `components/password-dialog.tsx` | `app/recordings/actions.ts` | `lib/gdrive/client`, `lib/gdrive/recordings` |
| `app/service/service-resources.tsx` | `app/admin/(dashboard)/files/actions.ts` | `lib/gdrive/client` |
| `app/resources/resource-viewer.tsx` | `app/admin/(dashboard)/files/actions.ts` | `lib/gdrive/client` |
| `components/committees/committee-files.tsx` | `app/admin/(dashboard)/files/actions.ts` | `lib/gdrive/client` |

### Issue 2: Unused Server Actions Still Exist
The following server actions are no longer used (pages use API proxy via hooks), but still import GDrive modules:
- `app/recordings/actions.ts` - `fetchRecordings()` (unused, but `verifyFolderPassword()` is still used)
- `app/newsletter/actions.ts` - `fetchNewsletters()` (entirely unused)
- `app/resources/actions.ts` - `fetchResources()` (entirely unused)

### Issue 3: API Route Eager Imports (MODERATE)
`app/api/gdrive/[type]/route.ts` imports ALL GDrive modules at top level:
```typescript
import { getRecordings, getRecordingYears } from "@/lib/gdrive/recordings"
import { getNewsletters, getNewsletterYears } from "@/lib/gdrive/newsletters"
import { getResources, getResourcesByCategory, getOldConferenceReports } from "@/lib/gdrive/resources"
// ... etc
```
Even when only one type is requested, all modules are bundled.

```typescript
  // ... DB-only implementation (no GDrive imports)

```

#### 1.2 Update imports in client components
| File | Change |
|------|--------|

### Phase 2: Clean Up Unused Server Actions

#### 2.1 Delete unused functions
| File | Action |
|------|--------|
| `app/recordings/actions.ts` | Remove `fetchRecordings()`, keep only `verifyFolderPassword` and DB functions, **remove GDrive imports** |
| `app/newsletter/actions.ts` | **Delete entire file** (no longer used) |
| `app/resources/actions.ts` | **Delete entire file** (no longer used) |

#### 2.2 Refactor `app/recordings/actions.ts`
Keep only DB-related functions:
- `getRegisteredFolderIds()`
- `getRegisteredFolders()`
- `verifyFolderPassword()` (redirect to new location or keep with no GDrive imports)

### Phase 3: Use Dynamic Imports in API Route

#### 3.1 Convert `app/api/gdrive/[type]/route.ts` to use dynamic imports

**Before:**
```typescript
import { getRecordings, getRecordingYears } from "@/lib/gdrive/recordings"
// ... all imports at top
```

**After:**
```typescript
// Remove top-level GDrive imports

case "recordings":
  const { getRecordings, getRecordingYears } = await import("@/lib/gdrive/recordings")
  // ...
  
case "newsletters":
  const { getNewsletters, getNewsletterYears } = await import("@/lib/gdrive/newsletters")
  // ...
```

### Phase 4: Graceful Degradation for File Loading (IMPORTANT)

**Goal:** Pages should NOT fail completely if GDrive files cannot be loaded. Instead, show the page content without files.

#### Current Behavior (Problem)
```tsx
// CommitteesLoader currently shows error state:
if (error) {
  return <GdriveError error={error} onRetry={refetch} />
}
```

#### Desired Behavior
- Show page content (committee info, contacts, etc.) regardless of file load status
- If files load successfully, show file sections
- If files fail to load, silently omit file sections (no error displayed)
- Only show loading state briefly, then proceed with or without files

#### 4.1 Update Loader Components
Modify each loader to gracefully degrade:

| Loader | Change |
|--------|--------|
| `app/committees/committees-loader.tsx` | On error, render content with empty files instead of error state |
| `app/service/service-resources-loader.tsx` | On error, show "No resources available" message |
| `app/resources/resources-loader.tsx` | On error, show page structure with "Unable to load" message per section |

**Example for CommitteesLoader:**
```tsx
export function CommitteesLoader({ committees }: CommitteesLoaderProps) {
  const { data, isLoading, error } = useCommittees()

  if (isLoading) {
    return <GdriveLoader message="Loading committee files..." />
  }

  // Graceful degradation: show committees without files on error
  // Log error for debugging but don't block the page
  if (error) {
    console.error("Failed to load committee files:", error)
  }

  const committeeFiles: CommitteeFiles = data || {}
  return <CommitteesContent committees={committees} committeeFiles={committeeFiles} />
}
```

### Phase 5: Refactor Admin Files Actions (Optional - Lower Priority)

The admin files page (`app/admin/(dashboard)/files/actions.ts`) still imports GDrive modules, but this is an admin-only page that:
1. Is behind authentication
2. Has `dynamic = "force-dynamic"`
3. Doesn't affect public pages

**Recommended approach:**
- Move `verifyFilePassword` to the new shared location (Phase 1)
- Keep the rest as-is for now (admin-only functionality)
- Consider lazy-loading folder tree in future if admin page also crashes
